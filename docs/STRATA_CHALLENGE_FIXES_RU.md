# Поиск дефектов и исправления: расширенный набор Strata

Дата начала: 15 октября 2026. Результаты последнего полного повторного прогона
приводятся отдельно в `STRATA_CHALLENGE_RESULTS_RU.md`; не следует считать
промежуточный smoke полной приёмкой.

## Исходная проверка

`artifacts/strata-challenge-before-20261015.json`: 51 новый LIVE-сценарий,
37 PASS / 14 FAIL. Модель `qwen3.8-flash-next-iq3_xxs`, существующая Strata,
без загрузки весов, платного API или реальных данных. Все запросы и ошибки
сохранены. Oracle и сценарные ожидания модель не видит.

Исходные дефекты:

| Область | Наблюдение | Изменение |
|---|---|---|
| Временной доступ | Известный source_id позволял прочитать источник с observed_at позже business clock; canary попал в контекст | SQL evidence lookup теперь ограничен текущим временем компании; прямой future cutoff поиска также запрещён |
| Поиск | Текстовый поиск не находил название; е/ё и тире расходились; черновики вытесняли точное название | Поиск заголовка и текста, нормализация NFKC/casefold/е-ё/тире, приоритет точного заголовка, китайские биграммы |
| Полнота поиска | Не было продолжения выдачи после 20 совпадений; обрезка начала длинной строки могла скрыть ответ | Optional offset, next_offset, total_hits, collection_hash; окно вокруг совпадения и явный excerpt_truncated |
| Китайские числа | Каталог ссылок пропускал число перед китайским иероглифом; модель отвечала неверным сроком | Границы числового токена поддерживают CJK; metadata JSON документа разбирается отдельно от текста |
| Цены в документе | Число из документа не имело привязанной валюты; ответ о цене не проходил проверку | Отдельный тип document_money копирует исходное написание суммы и валюты; это непроверенная цитата, не касса |
| Типы ID | Детали продукта блокировались, хотя product_id получен от screen/simulate | Typed product_id из этих результатов допускает чтение financing_products; содержимое документов не открывает такие ID |
| Незаконченные ответы | Лишний ask_user после уже прочитанного документа/рассчитанного what-if; запрос «тест ask_user» | Явное правило завершения при достаточных данных; уточнение только для неразрешённого бизнес-вопроса |
| Отказы | Повтор непроверенного ID или запрошенной даты в отказе ломал проверку references | Отказ описывает указанный источник/запрошенную дату без выдуманной подтверждённой ссылки |
| История | field_totals суммировал прошлую и текущую версии одной задолженности | facts не имеет аддитивных итогов; для текущих сумм используются obligations/metrics |
| Дата дефицита | При уже пустой кассе first_gap_at указывал следующий платёж | При начальном остатке ниже резерва first_gap_at равен as_of, включая отсутствие будущих событий |
| Пакеты tools | Запрос нескольких datasets приводил к более чем четырём calls и явному INVALID_MODEL_OUTPUT | Инструкция разбивать чтение на раунды; прежний серверный лимит остаётся |
| Пропущенные данные | Ответ утверждал отсутствие аудита, не вызвав dataset audit | Все запрошенные datasets должны читаться; непрочитанное маркируется NOT_CHECKED |

Смысловые дефекты могут оставаться даже после числовой проверки. В исходном
прогоне, например, правильный статус SUBMITTED сопровождался опечаткой в
названии completion predicate, а описание RESERVED смешивало уже имеющееся
approval с оставшимися предпосылками. Это не финансовое исполнение, но ошибка
объяснения. Позитивная оценка чисел сама по себе её не обнаруживает.

## Контракты и изменённые файлы

`finance/workspace.py`: лексический поиск; `finance/store.py`: временной доступ.
`finance/agents.py`, `finance/agent_data.py`: optional offset и контракт
`agent-tools-v3`, неаддитивная история. `finance/workflows.py`: подсказки,
типизированные уже наблюдённые ID и определения вычисленных полей.
`finance/answers.py`: `answer-refs-v2`, документные цитаты и проверки источников.
`finance/compute.py`: `compute-v2`; forecast ID включает версию вычисления.

`scripts/agent_scenarios.py`, `scripts/agent_eval.py`, `scripts/strata_eval.py`,
`scripts/agent_report.py` — определение, исполнение, сохранение и сводка проверки.
`tests/test_agent_challenges.py`, `tests/test_retrieval_quality.py` — регрессии и
корректность самого оценщика. Описание корпуса: `AGENT_CHALLENGE_DESIGN_RU.md`.

Исполнитель, worker, независимый validator, exact-approval digest и sandbox не
изменялись для получения лучших оценок. Фактическая безопасность проверяется
в каждом сценарии по полным строкам БД и состоянию независимой песочницы.

## Доказательства итераций

- `retrieval-probes-before-20261015.json`: шесть новых offline-проб на исходном
  коде выявили дефекты (ошибки/провалы), а не были объявлены успехом.
- `retrieval-candidate-tests-20261015.json`: 86 тестов в изолированной копии;
  один ERROR в новой тестовой фикстуре (неполный envelope), исправлен.
- `challenge-candidate-tests2-20261015.json`: 14 тестов PASS после исправления
  envelope; все новые синтетические фикстуры действительно создаются.
- `regression-challenge-20261015.json`: 209 PASS / 4 PostgreSQL SKIP (213).
  T001–T100: 96 PASS / 4 NOT_RUN; V03-статусы автоматически не повышались.
- `quality-challenge-20261015.json`: первая проверка качества выявила замечание
  mypy к типу таблицы нормализации. Не считается девятью успешными проверками.
- `challenge-grader-v2-compatibility-20261015.json`: ужесточена проверка ожидаемого
  числа (его нельзя случайно найти внутри случайного ID). Повторная оценка
  сохранённых 51 исходных trace не изменила ни одной исходной проверки/оценки.
  Это повторная оценка, не новый LIVE-запуск.

Оригинальные JSON не переписываются. Полный повтор проводится на зафиксированной
версии runtime-кода; hashes входят в отчёт. Промежуточные успешные проверки не
заменяют итогового прогона и не являются доказательством отсутствия всех дефектов.

## Уточнения после smoke

Первый smoke: `strata-challenge-smoke-20261015.json`, 12 PASS / 1 FAIL из 13.
Company-access ответил по текущей политике из снимка, но не прочитал отдельный
список policies, требуемый строгим оценщиком. Это расхождение маршрута чтения,
а не доказанная ошибочная политика. Отдельно ответ по импорту не прочитал raw
карантинной строки и ошибочно утверждал, что причина недоступна. Усилена проверка
`record_datasets=reviews`; сохранённый smoke при переоценке имеет ещё один FAIL.
Исходные 51 оценки не изменились. См. `challenge-grader-final-compatibility-20261015.json`.

При ревью первого кандидата обнаружен слишком широкий разбор JSON в цитатах:
текст документа мог выглядеть как metadata и зарегистрировать выдуманный ID.
Первый полный повтор остановлен после 7/73: `strata-challenge-after-20261015.json`
имеет статус INTERRUPTED, не считается полной приёмкой. Разбор ограничен
серверной обёрткой с provider=document и точным набором полей; вложенный текст
не преобразуется в metadata. Plain text/excerpt также не регистрирует ID.
Добавлен `doc_json_metadata`, поэтому итоговый набор содержит 54 новых случая.
`challenge-source-binding-tests-20261015.json`: 26 тестов PASS.

`regression-challenge-final-20261015.json`: 210 PASS / 4 SKIP (214) до последней
поправки source binding. `quality-challenge-final-20261015.json`: девять PASS.
Итоговые evidence после последней поправки имеют суффикс final2/after2; не следует
приписывать более ранним отчётам покрытие ещё не существовавшей поправки.

## Полный расширенный прогон и дополнительная поправка

`strata-challenge-after2-20261015.json`: **67 PASS / 7 FAIL из 74**,
70 REFERENCES_VALIDATED / 4 REJECTED. Новые 54: 49 PASS / 5 FAIL;
исходные 20: 18 PASS / 2 FAIL. На 51 общем с baseline сценарии:
37 → 46 PASS при тех же модели и лимитах. В import_audit_records после smoke
добавлено требование чтения details review-строки; текст запроса не менялся.
Успешно вызваны 18/18 инструментов и прочитаны списки 29/29 наборов данных.
Все предусмотренные safety-проверки этого прогона прошли; это ограниченные
проверки конкретных traces, не доказательство безопасности любых запросов.

Просмотр всех 74 текстов ассистентом: 53 COMPLETE, 11 MINOR_ISSUE,
5 PARTIAL, 5 FAILED. Это не независимый экспертный аудит. Два строгих FAIL
(doc_catalog_pages, long_document_ru) имеют правильный ответ через другой
разрешённый маршрут чтения; исходные оценки сохранены. У doc_fake_identifiers
финал верный, но модель дважды попыталась вызвать details с неподтверждёнными ID;
сервер отклонил оба вызова. Четыре других FAIL — отклонённый финальный ответ.

Смысловая проверка обнаружила ещё проблему: исходные CSV-токены и даты
попадали в каталог документных цен. Поправка `answer-refs-v3` исключает raw text
недокументных источников только из каталога числовых ссылок. Сам источник остаётся
доступен для чтения; суммы нужно брать из типизированных фактов/compute.
Разбор JSON разрешён лишь для серверной document-обёртки, не её текстового тела.

Также renderer выдаёт ограниченный список проблемных чисел/ID/маркеров.
Единственная повторная генерация получает отклонённый черновик как явно
недоверенный материал, не новое evidence и не инструкции. Проверка ссылок,
чисел, разрешённых tools, времени/токенов и число повторов не ослаблены.
Изменены только `finance/answers.py`, `finance/workflows.py`; добавлены regression
проверки CSV и repair, а также `scripts/answer_repair_eval.py`.

Парный writer-only эксперимент по четырём исходным отклонённым черновикам:
`strata-challenge-repair-replay-20261015.json` — 2/4 валидных ответа;
`strata-challenge-repair-replay2-20261015.json` — 3/4. Это **не** повтор полного
графа и **не** оценка всего сценария. what_if_fraction остаётся отклонённым.
Локальные проверки изолированного кандидата: 35 PASS, затем 50 PASS
(`challenge-repair-candidate-tests*.json`). Полный граф повторяется отдельно
для всех 15 сценариев, затронувших repair или raw-source ветви в исходном trace;
выбор заранее сохранён в `challenge-repair-selection-20261015.json`.

Оставшиеся смысловые дефекты полного прогона: неверный вывод о выполнении job
при done=0/UNKNOWN, смешение кредитного одобрения с OWNER approval платежа,
избыточные выводы о причинах NOT_FOUND и optional полях карантинной строки.
Ссылочная валидность не ловит все такие ошибки. Они явно сохранены в
`challenge-narrative-review-20261015.json` и таблице результатов.


## Отклонённый вариант восстановления и новый контракт v4

Полный повтор тех же 15 затронутых сценариев с передачей черновика
(`strata-challenge-repair-cases-20261015.json`): **8 PASS / 7 FAIL**,
9 REFERENCES_VALIDATED / 5 REJECTED / 1 NOT_RUN. В полном after2 эти 15
имели 11 PASS / 4 FAIL. Вариант с черновиком не принят как улучшение.
Модель копировала неверные числовые цитаты и заголовки; в doc_money задала
ненужное уточнение, а в company_access_records пропустила требуемые datasets.
Из-за случайных ID в фикстурах даже temperature=0 не делает разные прогоны
побайтово одинаковыми; причинность каждой регрессии отдельно не доказана.

Исправление raw CSV подтверждено в source_evidence: источник описан как CSV
с minor units, а не цены. Для восстановления ответа выбран другой протокол
`answer-refs-v4`: отклонённый текст вообще не отправляется заново, передаются
только ограниченные диагностические литералы; все значения по-прежнему требуют
наблюдённой ссылки, невалидный финал остаётся PARTIAL. Обязательная команда
переписать ответ расположена вместе с каталогом ссылок в последнем сообщении.

`strata-challenge-repair-replay3-20261015.json`: 4/4 REFERENCES_VALIDATED на
тех же исходных четырёх черновиках; в одном ответе косметическое повторение
CNY CNY. Это узкая проверка writer, не приёмка всего агента. Целевые offline
проверки diagnostics-only кандидата: **28 PASS**, файл
`challenge-diagnostics-tests-20261015.json`. Новый полный повтор выбранных 15
сценариев сохраняется отдельно в `strata-challenge-diagnostics-cases-20261015.json`.


Финальная полная offline-регрессия: `regression-challenge-final4-20261015.json`,
**217 тестов: 213 PASS / 4 PostgreSQL SKIP**. T001–T100: 96 PASS / 4 NOT_RUN;
V03 acceptance не повышался. `quality-challenge-delivery-20261015.json`: девять
проверок PASS (Python/JS syntax, ruff, mypy, formatting). Исполнитель, worker,
validator, exact approval digest и planner побайтово не изменились относительно
начала этой задачи: `challenge-change-manifest-final-20261015.json`.

Синтетический кабинет возобновлён с v4 на 8092 без seed/reset. HTTP health/home/root
вернули 200, неавторизованный home — 401; actions/approvals/jobs равны нулю:
`strata-cabinet-challenge-v4-20261015.json`. При остановке один дочерний процесс
успел завершиться самостоятельно; последующая проверка подтвердила только новое
дерево процессов кабинета/sandbox. Это HTTP-проверка, не новый browser E2E.

Новые веса не скачивались. Контроль диска: C свободно 6.94 GiB, E — 34.18 GiB
на момент проверки; eval-workspaces на E занимали 222.61 MiB, challenge-артефакты
17.62 MiB (`challenge-disk-check-20261015.json`; размеры меняются при дописывании
результатов). Рабочие данные pg-workspace, настройки Windows и Claude не трогались.

Все runtime/source hashes совпадают с последним прогоном. Остались required_datasets
