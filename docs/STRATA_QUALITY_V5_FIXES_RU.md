# Полнота чтения и смысл ответа: изменения 15 октября 2026

План: [AGENT_QUALITY_V5_PLAN_RU.md](AGENT_QUALITY_V5_PLAN_RU.md).
Исходное состояние файлов зафиксировано в `artifacts/quality-v5-before-20261015.json`.
Этот документ описывает реализацию; итог LIVE-прогона фиксируется отдельным отчётом.

## Реализация

- `finance/answer_quality.py`: ограниченная грамматика явных запросов чтения.
  Требования извлекаются из исходного пользовательского задания, при возобновлении —
  из сохранённого задания. Тексты документов и результаты инструментов не добавляют
  новых требований. Снимок не заменяет отдельно запрошенный реестр. Пустой успешно
  прочитанный список считается проверенным; ошибка чтения не считается пустым списком.
- `finance/workflows.py`: перед завершением проверяются требуемые чтения.
  При незавершённом чтении выбор инструментов сужается к недостающим спискам/страницам
  и уточнению пользователя. Все чтения выполняются обычными вызовами модели с прежними
  tenant/role/observed-ID проверками. Сервер не выдумывает вызовы в trace.
  Финальный отказ проверки допускает одну уже существовавшую попытку восстановления;
  бюджеты не увеличены. Повторно неполный ответ получает `PARTIAL`.
- Полнота страниц: проверяются начало с нулевого смещения, цепочка `next_offset`,
  идентичность запроса и хеша коллекции/записи. Для полного документа нельзя принять
  один хвост вместо всего содержимого. Полное чтение начинает с каталога документов.
- В модельную проекцию добавлены именованные состояния флагов задания, outbox,
  резервирования и отзыва подтверждения. Исходные флаги сохраняются. Отсутствие ошибки
  не является успехом; actor — инициатор задания; outbox acknowledgement — не settlement.
- `finance/answers.py`: контракт `answer-refs-v5`, ссылки на именованные состояния;
  запрет сырых чисел/ID и проверка точных финансовых ссылок сохранены.
- `finance/agent_data.py`: контракт `agent-tools-v4`. Чтение детали карантина возвращает
  `validation_diagnostic`: повторная проверка исходной строки существующим CSV parser.
  Это не принятие строки и не отмена исходного решения карантина. Пустые необязательные
  поля не объявляются ошибкой. Изменений БД/схемы/миграций нет.
- Ограниченные проверки противоречий в тексте: завершение незавершённых jobs,
  приписывание кредитного одобрения OWNER, выдуманное исключение временной причины
  недоступности источника. Это не универсальная проверка смысла. Указания модели
  дополнительно различают каталог кредитов и одобрение, сумму займа и денежный резерв,
  источник CSV и банковскую выписку, длину JSON и длину документа, отсутствие наблюдаемого
  подтверждения и отказ поставщика. Эти указания сами по себе не являются доказательством.
- `scripts/strata_eval.py`: в хеши измеренного кода включён новый модуль качества.
  Определения 74 сценариев, oracle, критерии оценки и бюджеты не изменялись.
- `tests/test_answer_quality.py`: негативные случаи неполных/чужих страниц,
  отсутствие реального чтения, внедрение инструкций через документ, повторно неполный
  ответ, статусные противоречия и реальная диагностика карантина без изменения данных.

## Границы доказательств

Во время полного прогона владелец уточнил язык: только English/Chinese. Поэтому
`strata-quality-v5-full-20261015.json` остановлен после 21/74 (20 PASS, 1 FAIL), это
**INTERRUPTED**, а не полный итог. Просмотр первых текстов отдельно зафиксировал
неподтверждённую связь договора с общей задолженностью в doc_injection_inline.

`scripts/agent_language_profile.py` добавляет проверенный профиль 54 EN / 20 ZH.
Переводятся только запросы/ответы на уточнения; исходные документы и oracle прежние.
`tests/test_agent_languages.py` проверяет полный состав 74, языки, неизменность всех
критериев/фикстур и отказ на непереведённом сценарии. Исходные `_ru` ID остаются ключами
сопоставления. У `strata_eval` новый параметр `--language-profile en-zh`. Распознавание
явного чтения расширено английскими member roles/current operations/compare.
Новая заморозка: `quality-v5-enzh-freeze-20261015.json`, 85 Python-файлов. Этот повтор
сравнивается с прежним только с оговоркой об изменившемся языке запросов.

Вторая LIVE-проба: 11 PASS / 1 FAIL из 12, все 12 ответа со ссылками прошли проверку.
FAIL у карантина — восстановленный вызов без обязательного `offset`, критерий не ослаблялся.
Просмотр также выявил неправильное направление DRAW_LOAN. Следующая итерация добавляет
его серверное пояснение и адресные проверки ложного исходящего платежа/денежного резерва,
а также выдуманного `completion_predicate`. Обязательность `offset` подчёркнута в схеме;
пропущенный аргумент по-прежнему отклоняется. Диагностика карантина теперь указывает
конкретные `invalid_integer_fields`, чтобы общий текст parser не приписывался обоим полям.
Для объяснения ошибки карантина требуется фактическое чтение диагностической детали.
Полностью прочитанную цепочку больше не обесценивает лишняя перекрывающаяся страница.
Адресный offline-пакет после этих изменений: 21 PASS.

В третьей пробе — 2 PASS / 1 FAIL; в четвёртой — 1 PASS / 1 FAIL.
Карантин завершился с правильным диагнозом конкретного поля. У delivery обнаружены
повторные неверные переходы между ID и ошибка собственной новой проекции: фактическое
поле jobs называется `finished`. Исправлена привязка, добавлена проверка на настоящей
операционной фикстуре вместо одного искусственного словаря. Именованные статусы/коды
включены в каталог ссылок; служебные OK/ERROR исключены. Номер строки не может выдаваться
за именованный код ошибки карантина.

В `known_records()` добавлены только серверные `action_id` из верхнего уровня записей
reservations/attempts/jobs/outbox. Они ведут к реальной существующей операции и позволяют
прочитать её статус без повторного поиска actions. Предложенные действия плана и поля
из документов таким правом не обладают; оба отрицательных случая проверены тестами.
В схеме чтения показаны соответствия ID конкретным реестрам. Серверная проверка пары
реестр/ID, tenant/role и обязательных аргументов сохраняется.

Пятая адресная LIVE-проба delivery — PASS; 22 целевых offline-теста — PASS. Последняя
реализация зафиксирована в `artifacts/quality-v5-freeze-20261015.json` (83 Python-файла).
Все 74 сценария повторяются последовательно без изменения этих исходников. Предыдущие
полные локальные регрессии сохранены как этапные, окончательная носит суффикс `frozen`.

Грамматика распознаёт ограниченный набор явных русских/английских формулировок. Она
не понимает произвольный естественный язык и не доказывает, что выбран правильный
поисковый фильтр. Китайский язык, перефразирования, смысл отдельных рекомендаций
по-прежнему требуют оценки модели и просмотра ответа. Пустой результат не доказывает
отсутствие скрытых или будущих записей. Не все разрешённые документы обязательно
поместятся в бюджет одного задания: в таком случае допустим честный `PARTIAL`.

Модули `execution`, `worker`, `validation`, `digest_check`, `planner` проверяются по
исходным хешам. Обязательные подтверждения, idempotency, reserves, UNKNOWN/status lookup,
tenant/role/cutoff, независимая песочница и сверка не ослаблялись. Реальные платежи,
реальные данные, платные API и загрузки новых моделей в эту итерацию не входят.

## Первый полный EN/ZH прогон и следующая коррекция

`strata-quality-v5-enzh-full2-20261015.json`: COMPLETED, 74/74, 66 PASS / 8 FAIL,
70 REFERENCES_VALIDATED / 2 REJECTED / 2 NOT_RUN. Все 18 tools и 29 datasets
покрыты; проверки безопасности без отказов. Просмотр всех текстов:
61 COMPLETE / 6 MINOR_ISSUE / 2 PARTIAL / 5 FAILED. Полный протокол сохранён в
`STRATA_QUALITY_V5_INITIAL_RU.md` и `STRATA_QUALITY_V5_INITIAL_ANSWERS_RU.md`.

Обнаружен дефект новой грамматики: «план и его действия» ошибочно требовал
реестр исполненных actions после подготовки proposal. Это исправление нашей
проверки полноты, а не отказ модели. Отдельный тест сохраняет обязательность
реального actions registry, если пользователь явно запросил его отдельно.

Версия `answer-quality-v2` также распознаёт буквальный search по названному
реестру и запрос «где подтвердить» как необходимость фактического чтения
`get_platform_capabilities`. Три одинаковых успешных read-вызова подряд завершают
tool phase: модель должна объяснить собранные данные, а недочитанные требования
по-прежнему дают PARTIAL. Разные страницы не считаются одинаковыми вызовами.
Отказ `PROTECTED_OR_INVALID_TERMS` в предложении отсрочки также закрывает tool
phase и требует объяснить отказ вместо необязательного дальнейшего уточнения.
Ни одна из этих ветвей не разрешает исполнение, подтверждение или обход запрета.

Серверные пояснения различают список preconditions и их текущую проверку,
отсутствие outbox acknowledgement и фактическую доставку, входящие/исходящие
obligations и платёжный статус отдельного инвойса. Это контекст для модели,
не доказательство универсального понимания. Исходные сценарии, перевод EN/ZH,
oracle и grader остаются неизменны. Новый полный повтор имеет отдельное имя
`strata-quality-v5-enzh-full3-20261015.json`. Целевые offline-проверки — 27 PASS.

Следующий полный повтор `strata-quality-v5-enzh-full3-20261015.json` остановлен
на 11/74 (8 PASS / 3 FAIL): новый ограничитель повторов сравнивал отсутствующие
