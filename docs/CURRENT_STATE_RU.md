## Стратегии планирования

Семантика общей функции `planner.objective_scope()` используется CP-SAT и
переборным тестовым oracle. Она изменилась относительно v0.2.

| Стратегия | Цель и ограничение |
|---|---|
| `MIN_COST` | Минимальная стоимость финансирования, затем минимальная основная сумма, с соблюдением резерва |
| `NO_NEW_DEBT` | Финансирование исключено; план возможен только с доступными деньгами и установленными датами |
| `HIGHER_RESERVE` | Минимальная стоимость при заданном `reserve_target_minor`; по умолчанию цель составляет 125% обязательного резерва |
| `PRESERVE_LIQUIDITY` | Соблюдение резерва во всех заданных сценариях; без явного набора используются f0, delay_5 и delay_25 |

`HIGHER_RESERVE` больше не максимизирует заём ради остатка денег, а
`PRESERVE_LIQUIDITY` больше не является копией `MIN_COST`. Область поиска остаётся
конечной сеткой DEMO-продуктов и сумм: максимум один финансовый продукт,
фиксированные подтверждённые даты платежей. Объяснения невыполнимости —
диагностические проверки, а не доказательство минимального набора конфликтов.

## Подтверждение и завершение задачи

События задачи: `OPENED → PROBLEM_CHANGED / OPTIONS_COMPUTED / OPTION_SELECTED → CLOSED`.
Выбор варианта не закрывает задачу. Причина закрытия
`RESOLVED_SETTLED_AND_RECONCILED` требует завершённого выбранного плана и совпавшей
сверки. Если разрыв исчез из новых данных без такого исполнения, используется
отдельная причина `NO_LONGER_DETECTED_IN_DATA`.

На каждое действие требуется точное подтверждение OWNER. Браузер отправляет
`payload_hash` и явное подтверждение; сервер пересобирает команду. Изменение хэша
блокирует исполнение. Затем сохраняются прежние проверки полномочий, версий,
получателя, денег, зависимостей, резервирования и идемпотентности. `UNKNOWN`
сохраняет резерв и требует поиска статуса по прежнему ключу перед повторной отправкой.

Новые подтверждения имеют дополнительный **реальный TTL 24 часа**, независимый
от synthetic business clock. Старые подтверждения без записи `approval_ttl`
сохраняют только прежнее истечение по бизнес-времени. Это совместимость текущего
кода, а не миграция всех старых подтверждений на новый TTL.

Сессия действует 8 часов реального времени; logout отзывает её, каждый запрос
проверяет действующее membership. Cookie — HttpOnly и SameSite=Strict; Secure
включается под HTTPS. Cookie POST требует `X-SME-Request: 1` и проверки origin.

## Возможности агента и границы

Адаптеры: `mock`, `disabled`, `ollama`, `strata`. Последний требует отдельного
разрешающего флага и токена локального SSH-моста. Панель передаёт ссылки на открытый
контекст; сервер проверяет доступ к плану, принадлежность действия указанному
плану и наличие обязательства в текущем snapshot. Сохранение UI-контекста само
по себе проверяет форму ссылок. В `compose_task()` значение `case_id` пока только
включает общий текст о текущей задаче; отдельный `action_id` без `plan_id` не
проверяется и не добавляется в фактический контекст. Полная проверка каждого вида
ссылки не реализована; последующие инструменты сохраняют собственную авторизацию.

Карточки берутся из сохранённых результатов инструментов. Статусы вычисления,
workflow, текста и исполнения разделены. Наличие текста означает завершённую
генерацию, но не его финансовую корректность: он помечен
`MODEL_NARRATIVE_NOT_FINANCIAL_EVIDENCE`.

**Текущий приоритет — путь владельца.** 14B остаётся временной интеграционной
моделью. Новые прогоны Strata разрешены владельцем отдельно. CompletionGate,
проверка AnswerBundle/текста, оптимизация scoped tools, профиль холодного/тёплого
запуска, LIVE E2E с исполнением и китайский holdout остаются незавершёнными.
Исторические 14B-измерения сохраняются; они не доказывают качество агента v0.3.
В Strata обнаружены повторные ошибки масштаба денежных сумм в тексте при верных
результатах инструментов. Успешная автоматическая оценка вызовов не означает
финансовую корректность ответа.

проверять отдельно, старые PID и номера сессий не являются текущим состоянием.
